## What happened

- Reproduced the CI lint locally with the real config and the correct diff base:
  13 issues in `server`, **0 in agent**. The agent job had never actually run,
  so that was worth checking rather than assuming.
- Fixed all 13: threaded a real `context.Context` through the three store
  methods instead of silencing `noctx` with `context.Background()`; made the
  column migration return an error instead of swallowing it; cleared 7 shadow
  declarations; fixed `colours`.
- Added `make lint-go`, because `make lint` runs `go vet`, which enables none of
  the four linters that caught me.
- Rewrote the release to publish to GHCR with the automatic `GITHUB_TOKEN`, for
  amd64 and arm64, with provenance and SBOM, **before** creating the tag.
- Hardened the image: unprivileged runtime, BuildKit target architecture,
  trimmed binaries, no curl.

## Defect worth remembering

Running the server unprivileged would have taken production down. The database
from the previous root-running image is `root:root 0644`; uid 10001 cannot open
it. Reproduced against a copy of a real database first, which turned a
would-be outage into a fix. The entrypoint adopts the data directory and then
`exec`s through `su-exec` so SIGTERM still reaches the server — `docker stop`
exits 0 rather than 137.
