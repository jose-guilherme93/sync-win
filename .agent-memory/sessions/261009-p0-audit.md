## What happened

Worktree `sync-win-p0-verify`, branch `fix/scan-device-null-and-p0-audit`, based
on `develop` @ `232cd65` (content of the released `v0.6.10`).

### The scope correction

The task started as "finish P0.1-P0.5", but `context/p0-remediation.md` still
described them as pending while `5bd1057 security: complete P0 remediation`
(2026-09-25) had already shipped them in `v0.6.10`. The stale handoff misled the
plan; it is corrected in this branch.

### 1. Device reads tolerated no NULL

`scanDevice` and `ListDeviceSummariesForOwner` scanned nullable text columns
(`last_seen_at`, `last_sync_at`, `last_error`, `last_error_at`, `hardware_json`,
`apps_json`) into plain `string`. A NULL row — reachable from a seed script, a
migration or a manual insert, not from the normal writers — made `/api/devices`
return a 500. Scanned them as `sql.NullString` and `COALESCE`d the summary
query. Regression test fails on the old code with "converting NULL to string is
unsupported".

### 2. P0 re-audit (P0.1-P0.5) — verified clean

Ran a real server (`go run ./cmd/server`, port 8091) and probed it:

- P0.1 owner isolation: account B could not read account A's device on any of
  detail/logs/files/docker/services/apps/ports/telemetry/updates/settings/
  attachments/security-audits (403/404/401), while A reached its own device
  (200). Anonymous requests were denied. Device-facing handlers authenticate
  with the device token, never a client-supplied owner id.
- P0.1 CSRF: a cookie-authenticated POST without the CSRF header returned 403.
- P0.2: changing the password returned 204 and the old session then returned 401
  from `/api/auth/me`; a wrong current password returned 400. Enrollment tokens
  expire in 15 minutes (`CreateEnrollmentToken`).
- P0.3: the login rate limit returned 401 ten times then 429 (10/min/IP). The
  webhook SSRF guard resolves once, rejects private addresses, pins the IP,
  disables the proxy and disables redirects.
- P0.4: Docker mutations returned 503 (read-only ops 200); `restore-saves`
  returned 503. Flags fail closed.
- P0.5: CI runs `golangci-lint`, `go test -race` for server and agent, and
  `npm run test/check/build`.

### 3. One gap hardened

`isPrivateIP` did not cover CGNAT (`100.64.0.0/10`) or other
non-globally-routable ranges (IETF assignments, benchmarking, TEST-NETs, 240/4,
2001:db8::/32). Added them to the SSRF filter with a regression test.

### 4. Build toolchain bumped off known CVEs

A production scan of the shipped image flagged two HIGH stdlib CVEs in both
binaries — `CVE-2026-78667` (`net/http` Range-header DoS) and `CVE-2026-97031`
(`crypto/tls` ECH DoS) — both fixed in Go 1.27.2. The image had been built with
Go 1.25.14 on Alpine 3.20 (EOL). Bumped the Dockerfiles and CI to Go 1.27, the
runtime base to Alpine 3.24, and both `go.mod` directives to 1.27. Trivy on the
rebuilt image: 0 HIGH/CRITICAL; both binaries embed `go1.27.2`.
